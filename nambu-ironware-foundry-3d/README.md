# 鉄瓶、うまれる。

岩手県の南部鉄瓶が、砂・火・鉄から生まれて暮らしの道具になるまでを体験する、タッチ操作主体の3Dモバイルゲームです。

製造過程を **48工程** に分解し、工程順を保ったまま **4章・14の主操作** に束ねています。直接操作しない工程も省略せず、同じ工房内の短い自動工程として連続再生します。

## リリース状態

**Version 1.2.0 — 連続形状・材質変化版**

ユーザー実機で判明した「円を描いても進まない」「開始から型挽きまで中心物体が変化しない」という問題を、判定値だけでなく、冒頭章の形状生成・材質表現・キャッシュ更新まで含めて作り直しました。

### 1.2.0で根本的に変更したもの

- 円操作を画面中央基準で判定する実装を廃止し、**画面上のどこへ描いても、その軌跡自身の中心と回転量を解析**する方式へ変更
- 指を離しても進捗を保持し、4歳児が複数回に分けて回せるように変更
- 最初の有効な数ピクセルの移動から、中心物体の半径・凹凸・圧密状態が変わるように変更
- 積み重ねた輪で形を擬似表現するモデルを廃止し、**一枚の連続BufferGeometry**へ置換
- 砂が低い山から上へ育ち、粗挽きで足・胴・肩・首が順に現れ、細挽きで大きなうねりと粒状凹凸が収まる連続変形を実装
- 側面だけでなく、少し盛り上がった上面も高さとともに変化
- 砂色、湿り、粗さ、光沢、頂点色、バンプ量、削り跡を工程進捗へ連動
- 淡色の台と大きな砂塊を廃止し、暗い木・鉄の回転台と細かな砂粒へ変更
- 工房内の可視ガイド円、接触マーカー、輪郭ゴーストを撤去
- 古いService Workerが壊れたJavaScriptを供給し続けないよう、HTML・JavaScript・CSSをnetwork-firstへ変更し、旧キャッシュ検出時に一度だけ再読込み
- 古い冒頭章の途中セーブを新しい形状生成へ移行せず、冒頭章から再体験させる保存データ移行を追加

詳細は [`CHANGELOG.md`](CHANGELOG.md) を参照してください。

## 写実性と4歳児向け補助

4歳児向けの補助は、工房内へ円、矢印、照準、成功範囲を浮かべる方法では実装していません。世界の見た目は保ったまま、次の値を別々に調整します。

- 入力の許容幅
- 動作速度
- 重量感
- 対象物の画面占有率
- カメラの高さと画角
- 砂塵量
- 溶湯の粘性、乱れ、太さ、発光
- 黒い艶
- UIと達成演出の存在感

設定には「写実優先」「4歳優先」「暗い工房」のプリセットがあり、各値をスライダーで微調整できます。設定は端末内へ保存されます。

## 起動方法

このフォルダを静的Webサーバーで公開し、`index.html` を開きます。

```bash
cd nambu-ironware-foundry-3d
python3 -m http.server 8000
```

その後、ブラウザで `http://localhost:8000` を開きます。ビルド工程はなく、フォルダの内容をそのままGitHub Pagesなどへ配置できます。

Three.js 0.154.0は、起動時にjsDelivr、失敗時にUNPKGから読み込みます。Service Workerが利用できる環境では、読み込んだライブラリも次回用にキャッシュします。

## 操作

- タップ：アラレ打ち、楔打ち
- 画面のどこでも大きく回す：型挽き
- 上下ドラッグ：取鍋、鋳込み、湯返し、鉉、最初の一杯
- 左右ドラッグ：運搬、型開け
- なぞる：砂落とし、研磨、黒仕上げ
- タイトル／工房閲覧：ドラッグして視点をわずかに変える

失敗しても工程の最初へ戻されません。物質の反応を見ながら、その場で入力を直せます。

## 保存

ブラウザの `localStorage` に、完了した48工程、完了した主操作、現在の場面、各工程の最良精度、プレイ時間、調整値を保存します。破損・旧形式・範囲外の保存値は起動時に正規化します。

## テスト

```bash
npm test
```

検証内容：

- 全JavaScriptとService Workerの構文
- 48工程の連番と重複のない割当て
- 4章の開始・終了工程
- 14主操作と対話工程の対応
- 画面中央から外れた円、複数ストローク、直線スワイプとの識別
- 最初の移動直後、半回転、粗挽き完了、細挽き完了の連続形状値
- 連続メッシュ実装と、旧リングモデルが残っていないこと
- 保存データの移行、重複排除、範囲制限、完成状態

Chromium受入テストでは、砂山の高さ成長、最初の数ポインタ移動での半径変化、途中輪郭、粗挽き完成を数値とスクリーンショットで確認します。ソフトウェアWebGL上の見た目は、実機iPadの最終画質評価の代替にはしません。
