# 鉄瓶、うまれる。

岩手県の南部鉄瓶が、砂・火・鉄から生まれて暮らしの道具になるまでを体験する、タッチ操作主体の3Dモバイルゲームです。

製造過程を **48工程** に分解し、順序を保ったまま **4章・14の主操作** に束ねています。直接操作しない工程も暗転で飛ばさず、同じ工房・同じ対象物の短い自動工程として連続再生します。

## 現在のリリース

**Version 1.3.0 — 冒頭の型挽きを根底から再構築**

実機で報告された次の二点を、入力値だけでなく、ヒットテスト、連続形状、材質、照明、保存移行、キャッシュ、ブラウザ受入テストまで含めて修正しました。

- 「指で大きな円を描く」で指を動かしても何も起きない
- そこへ至る自動工程でも、中心対象物が見た目上ほとんど変わらない

### 1.3.0で直した根本原因

1. 見た目上は消えていた読み込み画面が、CSSの詳細度により `display:flex` のまま残り、3Dキャンバスより前面でタッチを受け取っていました。
2. 透明になったフォールバック画もヒットテストに残っていました。
3. 円操作は画面中央を基準に角度を測っており、画面の端や対象物の近くで描いた円を正しく認識できませんでした。
4. 入力が通っても、対称形の物体を回すことが中心で、形状差と材質差が弱すぎました。

### 1.3.0の型挽き表現

- 読み込み完了後は、読み込み画面をレイアウトとヒットテストの双方から完全に除去
- フォールバック、ビネット、熱気、フラッシュ、説明帯など装飾層をタッチ対象から除外
- 画面のどこへ円を描いても、軌跡自身の中心・曲率・回転量を解析
- 途中で指を離しても進捗を保持し、複数ストロークで続行可能
- 最初の有効な数センチから、中心対象物の半径・輪郭・凹凸・材質値が変化
- 積み重ねた輪で形を偽装せず、**一枚の連続BufferGeometry**を毎フレーム変形
- 粗い砂塊から、底、胴の張り、肩、首、口周りへ連続的に収束
- 削った直後の淡い湿砂面を、物理的な接触線として表示
- 削り屑が回転台の周囲へ落ちて蓄積
- 粗挽きで粗さ・バンプを段階的に下げ、細挽きで大きなうねりと周方向の不整をさらに減少
- 型挽き中だけ作業灯、露出、霧を調整し、暗部へ輪郭が沈まないよう改善
- 古い冒頭章の途中セーブを一度だけ巻き戻し、新しい変形を最初から見せる移行を追加
- Service Workerのキャッシュ世代を更新し、旧JavaScriptを供給し続けない構成へ変更

## 冒頭章の連続変化

ゲーム開始後、中心対象物は次の順で変化します。

1. 回転台だけが見える
2. 粗い真土が低い状態から上へ連続的に盛られる
3. 不均一で大きな砂塊になる
4. 最初の指移動で外周が削れ始める
5. 半回転付近で底・胴・肩・首の差が読める
6. 粗挽き完了で鉄瓶外型の断面形状へ到達
7. 細挽きで表面の大きなうねり、粒状凹凸、周方向の乱れが減る
8. 注ぎ口、環付、尻型、蓋型、肌打ちへ同一対象物のまま続く

- 48工程の進捗保存と途中再開
- 完了工程への再挑戦
- iPad横画面・縦画面、マウス、タッチ対応
- Safe Area、画面回転、Reduced Motion対応
- 工程別の形状・材質・照明・粒子変化
- 湾曲する溶湯、砂塵、火花、蒸気、飛沫
- Web Audioによる炉、砂、鉄、溶湯、水、打撃の生成音
- 対応端末での触覚フィードバック
- 端末負荷に応じた描画品質調整

- 写実優先、4歳優先、暗い工房のプリセットと詳細スライダー

4歳児向けの補助は、工房内へ円、矢印、照準、成功範囲を浮かべる方法では実装していません。入力許容幅、動作速度、吸着、誤操作からの復帰を内部で調整します。

## 起動

```bash
cd nambu-ironware-foundry-3d
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。ビルド工程はありません。フォルダをそのまま静的ホスティングへ配置できます。

Three.js 0.154.0をjsDelivrから読み込み、失敗時はUNPKGへ切り替えます。Service Workerが利用できる環境では、初回成功後にアプリシェルとライブラリをキャッシュします。

## 操作

- タップ：アラレ打ち、楔打ち
- 画面のどこでも大きく回す：粗挽き、細挽き
- 上下ドラッグ：取鍋、鋳込み、湯返し、鉉、最初の一杯
- 左右ドラッグ：運搬、型開け
- なぞる：砂落とし、研磨、黒仕上げ

失敗しても工程の最初へ戻しません。物質の反応を見ながら、その場で入力を修正できます。

## テスト

```bash
npm test
```

静的・状態モデル検査に加えて、GitHub ActionsのChromium受入テストで次を確認します。

- 読み込み完了後の `#loading` が `display:none` かつ `pointer-events:none`
- 指の開始点で `elementFromPoint` が `#gameCanvas` を返す
- 真土が低い状態から36段階で上へ成長する
- 最初の数ポインタ移動で、ゲーム進捗とメッシュ半径が変わる
- 削った直後の湿砂面が現れる
- 半回転で鉄瓶外型の強い輪郭差が現れる
- 粗挽き完了後に目標輪郭へ到達する
- 細挽き途中・完了で材質の粗さ、バンプ、周方向不整が減る
- JavaScriptの実行時エラーがない

受入テストは各段階のスクリーンショットと数値状態をGitHub Actions artifactへ保存します。SwiftShader上の速度や最終画質は、実機iPadの評価とは分けて扱います。
