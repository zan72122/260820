# ユニコーンと、にごった泉

4歳児向けの短編3DモバイルWebゲーム。雨上がりの朝、森の泉に黒紫色の濁りの筋が漂っている。ユニコーンの角先を水へ近づけ、指で円を描くと、濁りが一本だけ角の螺旋溝へ巻き上がり、その真下の水が澄む——「ぐるぐるすれば水がきれいになる」という理解が、説明なしで子ども自身の手の中で立ち上がることを最優先に設計している。

## 遊び方

- 対象: iPhone / iPad の Safari（縦・横どちらも可）。一指のみ。文章による説明はない。
- 起動 → 泉の全景 → ユニコーンが屈む → 接写。水面付近を指でなぞり、円を描くと最初の濁りが巻き取れる。
- ゆっくり回すと密な細い螺旋、速く回すと幅広いリボン。小さな円は近くの筋だけ、大きな円は離れた筋も引き寄せる。逆回転は失敗ではなく、巻いた濁りが一度ふわりと緩んでから再び捕まえられる。
- 濁りを取るたび、水底の小石・水草・小魚・沈んだ木の実が現れる。全て取り除くと魚が活発になり、ウサギが水を飲みに来る。
- 巻き取った濁りは消えず角の溝に残る。泉の外の黒い多孔質の浄化石へ角を向けると、乾いた鉱物粉として移る。
- 浄化後は自由遊び（小さな濁りが時々再生する）。右下のグリフでリプレイ。

## 開発

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run typecheck
npm run e2e        # Playwright (Chromium)。CLAUDE.md のクラウドプロファイル準拠
npm run build
```

`?e2e=1` で固定シード・低負荷モード・`window.__game` テストブリッジ（phase / clarityAvg / fastForward 等）が有効になる。`&hq=1` を足すと E2E でも最高品質段階で描画する。

## 実装方式（要点）

- **Vite + TypeScript + Three.js r170 (WebGL2 / WebGLRenderer)**。外部アセット・ネットワーク通信・分析・広告なし。テクスチャは全て起動時に Canvas で生成（シード付き乱数）。
- **流体シミュレーションは行わない**。水面は実ジオメトリ＋解析的リップル法線。濁度は低周波ノイズ×「透明度マスク」（256px Canvas、角先から連続的に塗られる）。水底・魚・水草は最初から存在し、マスクと深度で遮蔽だけが変わる。
- **濁りの筋**はスプラインに沿うCPU更新リボン（40サンプル×11本）。巻き取りは各サンプルを水中カーブ→角の螺旋溝ヘリックスへ遅延付きでブレンドする。子どもの回転速度がヘリックスのピッチとリボン幅に残る。
- **ユニコーン**は小柄な馬の体格でプリミティブから構成。首は明示的ピッチ/ヨー角のIK（4反復×2関節）で角先を目標へ向け、届かない分は体全体の前傾（体重移動）が補う。首だけが伸びることはない。
- **カメラ**は固定ショットの連続鎖（全景→中景→接写→わずかな追従→浄化後の引き）。自由カメラなし。最初の因果の瞬間はカットしない。
- **音**は全てWebAudioで合成（滴・蹄・水面接触・巻取り・澄んだ水・粉・鳥）。チャイムやファンファーレは使わない。
- **入力**は一指のみ。移動履歴の重心まわりの累積回転角と角速度から円運動の意図を推定する。厳密な円は要求しない。反応点（角先）は指より約8.5%上に置き、指が因果を隠さないようにする。
- **品質制御**: devicePixelRatio をそのまま使わず（上限2）、実測フレーム時間の75パーセンタイルで内部解像度を4段階に増減する。

## 既知の制約

- 実機 iPhone/iPad Safari では未検証（本環境からアクセス不可）。検証はヘッドレスChromium（SwiftShader）での実測とビューポートエミュレーションによる。FPS・発色・タッチ感触は実機での確認が必要。
- WebGPURenderer ではなく WebGL2 を採用（カスタムシェーダ3系統の安定性とiOS Safariの互換性を優先）。浄化・巻取り・再プレイの全てがWebGL2で成立する。
- 縦画面接写では画面上の角の対角線が「左上→中央下」になるよう配置しているが、腕の利き手による見え方までは個別最適化していない。
