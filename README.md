# 虹の軌跡織り — Rainbow Trail Weaving

ブランコの往復運動そのものを絵筆にする、iPhone / iPad 向けのモバイル Web ゲームです。
画面に指で線を描くのではなく、**こいだブランコの座面が夕方の斜光と細かな霧の交差域を横切った実際の軌跡**から、
world-space の 3D リボンとして分光色の弧が生まれます。

## 起動

```bash
npm install
npm run dev        # 開発サーバ (http://localhost:5173)
npm run build      # 静的ビルド -> dist/
npm run preview    # ビルド結果を配信 (http://localhost:4173)
npm run typecheck  # tsc --noEmit
npm test           # Playwright (Chromium, iPhone/iPad プロファイル)
```

`dist/` は完全な静的サイトです。外部アセット・外部通信・ログイン・課金・広告はありません。

### URL パラメータ

| パラメータ | 意味 |
| --- | --- |
| `?fast=1` | 決定論モード（固定シード、パーティクル削減、影オフ）。自動テスト用 |
| `?seed=<n>` | 公園のディテールと霧の乱れのシード |
| `?tier=low\|mid\|high` | 品質ティアの手動指定（既定は端末から推定） |

### 開発用ツール

```bash
node tools/capture.mjs        # 縦/横/iPad で各ビートのスクリーンショットを撮る (OUT=... で出力先指定)
node tools/study.mjs          # ブランコ架構・乗り手・ミストアーチの寄り検証ショット
```

どちらも `npm run preview` が 4173 番で動いている前提です。

## 操作

- **弧を描くように一本指でスワイプするだけ**です。ブランコが今進んでいる向きに沿って大きく弧を描くと、
  次の周期でポンプ動作が入り振幅が増えます。
- 早すぎる入力は捨てずに適切な位相まで保持され、遅い入力も小さな加速に変換されます。
- 逆向きのスワイプは反対の半周期のポンプとして扱われます（4 歳児の不正確な入力を罰しません）。
- 二本指のピンチ・回転・自由カメラはありません。二本目の指は完全に無視されます。
- 右上の丸い矢印は完成後だけ現れる「もう一度」です。説明文は一切出しません。

## 体験の流れ

1. 風で一度だけ小さく揺れる（誰も押していない）
2. 座面が霧を横切り、最初の淡い虹の弧が空間に残る
3. 数秒の間を置いて、ブランコの進行方向に沿う弧状スワイプの誘導を **一度だけ** 表示
4. 最初の入力で振幅が増え、前より大きな弧が残る
5. 大きな虹が出たら誘導は二度と出ない
6. 自発的な往復。振幅履歴に応じて内側の小さな弧・外側の大きな弧が重なる
7. 数往復後にカメラがわずかに上がり、重なりが見えるようになる
8. さらに続けると、同じ視点から連続して引きながら模様全体が読める位置へ（Reveal）
9. Reveal 後も空間はそのまま。ブランコを続けられる自由状態
10. 「もう一度」で織物だけを消し、同じ公園で再プレイ

カメラは一度もカットせず、弧の形成中に完成図・俯瞰・成功画面へ切り替わることはありません。

## 虹の生成方式

**唯一の魔法的規則**は「夕方の斜光を受けた細かな霧が、ブランコにかき乱された軌跡を数十秒だけ分光色として保持する」ことだけです。
それ以外（公園、ブランコ、乗り手、光、地面、植物、水）は現実の構造と材質に従っています。

### 軌跡ジオメトリ

- 座面**左右の縁**（world Z ±0.205 m）が実際に通った world-space の点列から、毎パス 2 本の 3D ribbon を生成します。
  画面に貼り付けた 2D 線ではないので、フレームやミストアーチと正しく前後関係を持ちます。
- サンプルは弧長 0.055 m ごと。1 本あたりのセグメント数は固定上限（96 / 128 / 160）。
- リボン幅は **速度と曲率** に追従します（最下点で最大）。入力の長さ・弧の深さ・時機が次の弧の太さと到達範囲を
  安全な範囲で変えます。
- リボンは進行方向まわりにゆっくりねじれ、後流としての立体感を持ちます。
- 頂点シェーダで、置いた後も微風によるドリフトと「持ち上がってからゆっくり沈む」挙動を与えます。
- 生成中はテーパを掛けて端を切り落としません。

### 分光色

- `src/trail/spectralLut.ts` が **CIE 1931 等色関数の多ローブ Gauss 近似**（Wyman et al.）から
  395–705 nm の連続スペクトル LUT を生成し、XYZ→sRGB で焼き込みます。七色の均等ストライプではありません。
- フラグメントシェーダは、**入射太陽光と視線のなす散乱角**、**霧粒径**、**リボン横断座標**から偏角を決め、
  LUT を折り返しサンプルします（赤から紫へ戻る継ぎ目は出ません）。
- 彩度は、実際に分散が集中する二つの幾何（反太陽側 ≈138° の虹帯、太陽方向近傍のコロナ/彩雲）で最も高くなります。
  それ以外の成分は白ではなく散乱した夕日の色として扱います。
- ブレンドは premultiplied alpha（`ONE` / `ONE_MINUS_SRC_ALPHA`）。アルファを色より低く出すことで、
  重なりが濁らず、散乱らしく光が加算されます。`depthWrite` は無効、`depthTest` は有効。
- 強い bloom は使いません。発光体ではなく、太陽光を散乱・屈折して見えている色として扱っています。
- 太陽高度がプレイ中にごくゆっくり下がるため、色相の重心が数分かけて少しずつ移動します。

## 性能上の対策

- **透明面の上限**: 同時に描く active ribbon は 8 / 12 / 14 本。古い弧は 1 枚の archive mesh へ
  リングバッファで焼き付けて統合するため、履歴がいくら増えても透明ドローは最大 15 本です。
- 統合済み archive は 1 ドローコール。頂点は固定スロットに上書きされ、再確保は起きません。
- 静物（ブランコ架構、ベンチ、樹木、ミストアーチ、遠景）はマテリアル単位でマージ。
  ドローコールは全景で 60 前後、Reveal 時でも 100 程度に収まります。
- 霧はフルスクリーンの volumetric raymarch を使わず、プールした point sprite と少数の soft sheet です。
- 霧粒・水滴はプール、草・小石・低木・遠景樹冠は instancing。
- 影は主要物のみ。遠景・草・小石は影を落としません。影マップは 512 / 1024。
- 高 DPI 端末では内部解像度を上限付きで制御し、平均フレーム時間が悪化したら段階的に下げます（0.72 まで）。
- 非表示タブ・バックグラウンドではパーティクル更新と音を停止します。
- WebGL 2 前提。外部の glTF / 画像 / 音声アセットは一切読み込まず、テクスチャは Canvas で手続き生成、
  音は WebAudio で合成します（ライセンス不明素材ゼロ）。

## サウンド

すべて WebAudio による手続き合成です。鎖の金属音、座面（ゴムベルト）の軋み、風切り、ノズルの細い噴霧音、
水滴、夕方の鳥、環境ベッド。虹のためのきらきらした高音を鳴らし続けることはせず、
**弧が 1 本完成した瞬間だけ**、水とガラスを模した短い音響イベントが鳴ります（弧が大きいほど低く長い）。
iOS の制約により、最初のタッチで AudioContext を起動します。

## 確認結果

`npm test` は Chromium で iPhone 13 縦 / iPhone 13 横 / iPad の 3 プロファイルを回し、次を実機同様の順で通します。

- 小さな自動往復（風の一押し）→ 最初の淡い虹
- 一回限りの操作誘導が出ること、誘導が虹の生成点を隠さない位置にあること
- 入力による振幅増加 → 大きな虹 → 誘導の消失（二度と出ない）
- 自発的な往復で内側/外側の弧が混ざること（振幅の最小と最大に有意な差があること）
- 軌跡が world-space であること（頂点の X/Y/Z が実際に広がっていること）
- 古い弧が archive mesh へ統合されていること
- カメラが raised → reveal → free と連続して進み、Reveal 後も自由に遊べること
- 画面回転で作品が失われないこと（弧の本数と頂点数が維持され、アスペクトだけ更新される）
- 実際の一本指スワイプ（弧を描く mouse/touch イベント）でブランコが加速すること
- 二本目のタップがジェスチャにならないこと
- 「もう一度」ボタンが入力レイヤ越しにタップできること
- 透明ドロー数の上限
- コンソールエラーが 0 件であること

内部解像度の自動調整も別途確認済みです。SwiftShader 上でフレーム間隔が 300ms 台に張り付く条件下で、
pixelRatio が 2.0 → 1.68 → 1.41 → 1.19 → 1.00 と段階的に下がることを計測しました。

## 既知の制約

- **虹は太陽を背にした側にできます。** 実際の光学どおり、反太陽側 ≈138° で分散が最も強く出るため、
  通常のプレイ画角では太陽の円盤そのものは画面外（カメラ後方左）にあります。太陽の方向は、
  暖色の順光、カメラ手前へ伸びる長い影、空のグラデーション、反太陽側の Belt of Venus と地球影で読めます。
  「遠景に低い太陽」を画角内に入れると虹の幾何が成立しないため、この一点だけ写実を優先しました。
- 検証は SwiftShader（ソフトウェア WebGL）上の Chromium で行っています。
  ロジック、ジオメトリ、構図、ドローコールは確認済みですが、**FPS・アニメーションの滑らかさ・最終的な発色は
  ハードウェア GPU の実機でのみ判断してください**。iOS Safari 実機での計測は未実施です。
- 樹木・低木は低ポリゴンの手続きジオメトリです。近景のヒーローマテリアル（鋼、ゴム、濡れた土、衣服、霧）に
  予算を寄せているため、中景の植生は形状の正しさ優先で、葉一枚単位の描写はしていません。
- WebGPU は使用していません（WebGL 2 で看板表現が成立するため）。
