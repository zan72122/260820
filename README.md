# うめの塩と太陽 — ポトポト、ザラザラ、じわじわ、ずらり

4歳児向けの短編モバイルWebゲーム。文字を一切読まずに、最初から最後まで遊べて、
すぐにもう一周できる。

中心にあるのは知識ではなく、ひとつの視覚的因果です。

> 白い塩を果物にたくさんかけると、どうなるんだろう
> → 塩粒が梅に落ちる → 粒が溶ける → 果皮に水滴が浮く
> → 日が過ぎる → 底に透明な液体がたまる → 液面が梅の間をじわじわ上がる

この連鎖を、**一度も画面を切り替えずに同じ構図の中で**見せます。
理解した直後にステージを終わらせず、同じ因果を何度でも触れる自由時間を置いています。

---

## プレイループ（一周およそ3〜5分）

| 場面 | 覚える因果 | 操作 |
| --- | --- | --- |
| 1. 初夏の梅畑 | 網は引くと地面に沿って広がる | 半分巻かれた収穫ネットの縁を一方向へドラッグ |
| | 時間が動くと熟した梅が自然に落ちる | 杭の**影**をつかんで振る（太陽が動く） |
| | 縁を持ち上げると梅が中央へ転がる | ネットの外周を上へドラッグ |
| | *自由時間* | 梅を突く、縁を上げ下げする、日をさらに動かす → 籠に触れて次へ |
| 2. 木の作業台 | 塩を梅にかけると水が出てくる | 木杓子を梅の上へ運ぶと傾いて塩が落ちる |
| | ただし**時間が過ぎないと液体は出ない** | 台に落ちた窓の光をドラッグ＝日が過ぎる |
| | *自由時間* | 別の場所に注ぐ、容器を回して滴を見る、液面をもっと上げる → 木蓋に触れて次へ |
| 3. 夏の天日干し | 日に当たった面だけ乾く | 梅を干し盆へドラッグ（近づけると吸着＋自動整列） |
| | 転がすと日の当たっていない面が出る | 梅を横へさっと払う |
| | *自由時間* | 並びを崩して整え直す、転がす、日差しを変える → 皿に触れて最初へ戻る |

進行はどのステージも「一度にひとつの未知の因果」しか出しません。
一度覚えた操作はその後ずっと自由に使えます。

### ヒント設計

チュートリアル、文章、矢印、案内音声は一切ありません。

1. 最初の3秒は完全な観察時間（何も動かない）
2. その後、**その場面で触るべき一つの物だけ**が風や反射で軽く揺れる
3. さらに数秒迷った場合のみ、方向を最後まで見せない短い予備動作を一度
4. 指が画面に触れた瞬間、ヒントは即座に消える
5. 一度成功した操作は2周目で弱く（0.4倍）、3周目で無音になる

## 主要技術

- **Vite 8 + TypeScript 5.9 + Three.js 0.185（WebGL 2）**
- **アセットはすべて実行時に手続き生成**。画像・音声・モデルファイルは1つも読み込みません。
  権利不明素材の混入がなく、追加ダウンロードは0バイトです。
  - テクスチャ: Canvas2D + value noise / fBm、法線マップは高さ場からSobelで生成
  - 効果音: WebAudio のオシレータとノイズバッファから合成（梅がネットに落ちる鈍い音、
    網が地面を擦る音、塩が木杓子と硝子に当たる乾いた音、液滴、盆に置く接触音を個別に合成）
- **Hero Materials 4種**
  1. 完熟梅 — 斑点・果粉・熟度差を持つ肌。濡れ／乾きを同一シェーダで表現し、
     天日干しでは**面ごとに**縮んで皺が入る（裏返すと日に当たっていない面が見える）
  2. 粗塩 — 角のある面（フラットシェーディング）＋擬似的な透過光で結晶感を出す
  3. 梅酢 — 実流体は使わず、深さで濃くなる液体メッシュ＋メニスカス＋壁を伝う筋＋
     果皮のroughness変化の組み合わせ
  4. 青い収穫ネット — アルファテストの織り目（**アルファブレンドを使わないので描画順問題が起きない**）
- **容器** — 内壁・外壁・巻き縁・厚い底を別ジオメトリで持ち、背面→中身→前面の順に描画。
  透明ソートに依存しません。
- **物理** — 独自の軽量球体ソルバ。質量は半径の3乗に比例、柔らかい低反発接触、
  地形勾配による転がり。固定ステップ積分なので30fpsでも120fpsでも同じ挙動になります。
- **ネット** — cloth simulationは使わず、巻き／展開／荷重の状態から毎フレーム頂点を再構成。
  同じ関数が物理の床の高さも返すので、**見た目と当たり判定が絶対にずれません**。
- **カメラ** — 35mm換算の焦点距離で設計（主に40〜52mm、塩と水滴では74〜85mmへ緩やかに寄る）。
  切り替えではなく移動のみ。画面サイズとsafe areaから毎フレーム再計算するため、
  回転しても工程は一切巻き戻りません。
- **描画品質** — low / balanced / high の3段階。devicePixelRatioに上限（1 / 2 / 2.5）、
  影キャスターと透明レイヤーを制限。フレーム時間から自動昇降格しますが、
  **SwiftShaderと判定した場合はfpsを根拠に品質を落としません**（機能検証と実GPU性能を分離）。

バックエンド、広告、分析SDK、個人情報収集は一切ありません。
進行状況は `sessionStorage` にのみ保存されます。

## 実行方法

```bash
npm install
npm run dev        # http://localhost:5173  （--host なのでLAN内の実機からも開けます）

npm run build      # 型検査 + 本番ビルド
npm run preview    # http://localhost:4173 でビルド結果を確認
```

URLパラメータ（開発・検証用）:

| パラメータ | 内容 |
| --- | --- |
| `?stage=orchard\|pickling\|drying` | 指定の場面から開始 |
| `?quality=low\|balanced\|high` | 品質段階を固定 |
| `?fast=1` | 検証用の軽量モード（DPR 1、決定的な乱数種） |
| `?manual=1` | requestAnimationFrame を止め、テスト側が論理時間を進める |

音量は右上のノブで 大 → 小 → 消音 と切り替わります（初回タップでiOSの音声解放も行います）。

## 実行したテスト

```bash
npm run typecheck   # tsc --noEmit
npm run build       # 型検査 + Viteビルド
npm test            # Vitest 78件
npm run e2e         # Playwright (Chromium) 11件
```

いずれもこのリポジトリ上で実際に実行し、全件通過しています。

**単体テスト 78件** — 純粋なモデルのみを対象にしています。

- `GameState` — 未知の因果は常に1つだけ提示される／覚えた操作は永続的に使える／
  進行は逆方向の入力でも巻き戻らない／全ステージを通って最初に戻る／スナップショット復元
- `BrineModel` — **塩だけでは液体が1滴も生まれない**／**時間だけでも生まれない**／
  最初の1粒でちょうど1つの水滴が浮く／液面が段階的に上がり、どの1日も全体の65%を超えて
  上がらない／大きな1回のドラッグと細かい40回のドラッグが同じ結果になる
- `DryModel` — 空を向いた面だけが乾く／裏返すと反対面が乾き始める／
  裏返すと良くなるが、裏返さなくても行き詰まらない
- `HintDirector` — 最初の3秒は無音／触れた瞬間に消える／2周目は弱く3周目は無音
- `Framing` — iPhone/iPad の縦横4寸法すべてで主要対象が切れず、safe areaにも掛からず、
  水滴と液面が下端の指の届く帯より上に残る
- `Quality` — SwiftShader判定でも立体構成を壊さない／DPRに必ず上限が掛かる／
  低fpsが続いた時だけ降格し、昇格には4倍の時間を要求する
- `Pile` / `gestures` — 接触音イベント、重さによる慣性差、勾配での収束、
  30fpsと120fpsの一致、曲がった遅いドラッグの方向判定

**E2Eテスト 11件** — `window.__ume` は状態の読み出しと「その物が今どこに描かれているか」の
問い合わせにのみ使い、**操作はすべて実際のポインタイベント**で行っています。

- 梅畑: ネットを引く → 影を振って梅が落ちる → 縁を上げて梅が集まる → 籠で次へ
- 漬け込み: 杓子を運んで塩を落とす → **この時点で液面が0であることを確認** →
  光をドラッグして日を進める → 液面・果皮の濡れが上がる → 木蓋で次へ
- 天日干し: 梅を盆へ並べる → 影を振って乾かす → 横に払って裏返す →
  裏面が乾き始めることを確認 → 皿で最初の梅畑へ戻る
- 回転: 縦→横→縦と変えても工程・進捗・シミュレーション値が一切巻き戻らない
- 乱暴な操作: 24連打、逆方向ドラッグ、ドラッグ途中でのフォーカス喪失を経ても停止せず、
  例外も出ない
- WebGLコンテキスト消失: `WEBGL_lose_context` で強制的に落として復元し、
  描画が再開し進行が保たれる
- 主要な操作対象が画面外や端26px以内に出ていないことを、掴む直前に毎回確認

**目視監査** — 縦横それぞれで初期画面／塩が落ちる場面／液面上昇／天日干し／自由遊びを
撮影し、自分の目で一度確認して修正しました。この監査で見つけて直した主なもの:

- 果実がプラスチックに見えていた（斑点・果粉・熟度差を強化し、
  一様なクリアコートを果粉に応じた粗さに変更）
- 木材が縞模様の羅列に見えていた（高周波の筋を削り、年輪を粗く柔らかく）
- 天日干しの縮み変形が**絶対値**で頂点を動かしており、4cm程度のメッシュが破裂していた
  （比率での縮小に修正）
- ネットの織り目が細かすぎてモアレになっていた
- ネットの縁が数センチではなく60cm以上持ち上がり、ハンモック状に浮いていた
- 木漏れ日が巨大な葉の塊になり、影の四角い境界線が地面に出ていた
- 天蓋が色を書かないまま深度を書いており、カメラが同じ高さに来ると全画面が消えていた
- カメラが寄った後に杓子・光・木蓋・皿・杭が画面外へ出ていた（配置を修正し、
  E2Eで毎回画面内チェックを追加）
- 画面アンカーの符号が反転しており、主要対象が上ではなく下に寄っていた（単体テストが検出）

## 既知の制約

- **実機では確認していません。** iPhone / iPad の実端末は手元になく、検証はすべて
  Linux上のChromium（SwiftShader、ソフトウェアラスタライザ）で行っています。
  したがって**fps、アニメーションの滑らかさ、最終的な見え方は未検証**です。
  CLAUDE.mdの方針どおり、SwiftShaderのfpsを根拠に品質を落とす処理は入れていません。
  GPU・視覚回帰・性能テストは、ハードウェア支援が確認できた実機かCIランナーで行ってください。
- safe areaの実測値はブラウザの `env(safe-area-inset-*)` に依存します。ノッチ端末実機での
  最終確認は未実施です。
- 梅酢に本物の屈折（`transmission`）は使っていません。シーンを2回描画する代償が
  携帯端末には重すぎるため、深度による着色・フレネル・メニスカスの組み合わせで表現しています。
  高性能端末でも屈折には切り替わりません。
- ネットは cloth simulation ではありません。巻き／展開／荷重の状態を補間しているため、
  端を掴んでねじるような自由変形はできません。
- 音は完全に合成音です。実録の環境音より抽象的に聞こえます。
- 影を落とす動的ライトは常に1灯までです。
- WebGPUは使用していません（WebGL 2のみ）。
- 進行は `sessionStorage` 保存のため、タブを閉じるとリセットされます。これは
  「すぐにもう一度遊べる」ことを優先した意図的な選択です。
