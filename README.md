# スライダー・ドクター つるつる大作戦

A touch-first 3D repair game for a four year old, built for Safari on iPhone and
iPad. The player never goes inside the slide: they stand at the inspection bench
and drive a small remote crawler into a dry water slide to find out why a test
droplet stopped, then put the joint right and prove it with water and an empty
raft.

There is no text to read, no failure state, no score, no timer, no ads, no
accounts and no network calls.

## Running it

```bash
npm install
npm run dev        # http://127.0.0.1:5173
```

```bash
npm run build      # type check + production bundle into dist/
npm run preview    # serve the production bundle
```

```bash
npm run typecheck  # tsc --noEmit
npm run test:e2e   # Chromium smoke pass, iPhone portrait + iPad landscape
```

The E2E suite starts the dev server itself. It runs Chromium only, one worker,
and is written to prove that a whole round can be played through — it makes no
judgement about frame rate or visual quality, which need a real GPU.

## How a round plays

1. **The mystery.** A test droplet runs into the flume, reaches a moulding joint
   and stops with a small dry click. Nobody explains why.
2. **The lamp.** A large knob at the bottom of the screen swings the crawler's
   inspection lamp. Only when the beam rakes across the joint does the lifted
   edge of the old caulk rise into the light and show the step beneath it.
3. **The work.** Peel the old strip off in one piece, scrub the channel, lay a
   fresh bead, draw it down with the blade, then bring the surface up with the
   pad. Each is one forgiving gesture; the tool tip is always drawn above the
   fingertip so a hand never covers the work.
4. **The proof.** Pull the lever: one droplet runs the joint without catching.
   Then the camera goes outside and an empty raft slides the repaired section in
   silence.

The first fault is always the step that stops the water. The second is a dull
patch that only slows it, taught with less help. From the third the faults
recombine and a tool tray appears, so the player predicts the tool instead of
being handed it.

## Layout

```
src/core/     renderer + adaptive resolution, scripted camera, gesture router,
              synthesised audio, procedural textures, dawn lighting probe
src/world/    the flume and its joints, the caulk, the crawler, the service
              heads, the droplet and raft, the park, shared shop materials
src/game/     world assembly and staged build, the shot chain, one class per
              treatment, and the run of play
src/ui/       HUD furniture and hand drawn SVG icons
tests/        Chromium smoke pass
```

## Rendering notes

- WebGL 2 through three.js. The whole game runs on WebGL 2 with no optional
  path required; nothing is gated behind WebGPU.
- Device pixel ratio is capped at 2 and multiplied by a dynamic render scale
  that reacts to measured frame time, so a weak device loses resolution and
  effects rather than frame rate.
- Lighting is one prefiltered probe generated from the sky, one key light, baked
  ambient occlusion in the bore, and a single shadow casting spot on the
  crawler that is dropped on the lowest quality tier.
- The joint the player is working on carries live colour, roughness and relief
  that are rebuilt from a small state grid, throttled well below frame rate.
- The translucent outer shell is skipped whenever the camera is inside the pipe,
  where it would be nothing but full screen overdraw.
