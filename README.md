# ひとつの心臓、四つの窓

iPhone と iPad の Safari で遊べる、4歳児向けの探索ゲームです。

臨床技能実習室の成人心音聴診トレーニングマネキンに聴診器を当て、**ひとつの
心臓から出ている同じ二拍が、胸のどこで聞くかによって少しずつ違って聞こえる**
ことを、子どもが自分の耳で見つけます。四つの聴診領域の名前を覚えさせる教材で
はありません。

## 起動方法

```bash
npm install
npm run dev        # http://localhost:5173 （--host 付きなので実機からも開けます）
```

本番ビルドとプレビュー:

```bash
npm run build      # 型検査 + production build
npm run preview
```

実機で試すときは `npm run dev` の出力に表示される LAN の URL を iPhone / iPad の
Safari で開いてください。

### 遊び方（最初の一分）

1. 器械台の**トレーニング用リスニングヘッドに挿さっている聴診器のイヤーチップ**を
   触ります。これが最初の操作で、これで音が始まります（別の「サウンド開始」画面は
   ありません）。
2. 指導者の手がチェストピースを胸の中央へ置きます。**指で押さえたまま**にすると、
   リムが沈み、診察室の音が下がり、心音が聞こえます。数拍そのまま聞きます。
3. 指導者がチューブのたるみを取ります。**指を胸の上で滑らせて**ください。場所に
   よって一つ目の音と二つ目の音の聞こえ方が変わります。
4. どこか一か所で数拍聞き続けると、短い内部Revealが入ります。
5. 次は**反対側の半分**へ誘導されます（下で見つけたら上へ、上で見つけたら下へ）。
   一回目に聞き比べる二か所は、必ず対比の大きい組み合わせになります。
6. あとは四つを行き来して聞き比べます。器械台に置かれた記録タイルを押すと、
   その場所の聞こえ方が今の心拍のまま再生されます。

点数も、制限時間も、星もありません。胸の上に丸印や光る場所も出ません。

## 何がどこにあるか

| モジュール | 役割 |
| --- | --- |
| `src/core/CardiacClock.ts` | 作品全体でただ一つの心拍タイムライン。音・心臓・胸の微動・タイル再生が全部ここを見ます |
| `src/audio/HeartSoundSource.ts` | 正常なS1・S2。M1/T1/A2/P2の四成分を起動時に一度だけ合成し、全部の聴取位置がその同じバッファを鳴らします |
| `src/audio/BodySoundField.ts` | 胸表面の連続音場。四つの領域は**音場のピーク**であって、当たり判定ではありません |
| `src/audio/AuscultationChannel.ts` | 一つの聴取位置を胸壁越しに鳴らす経路（ゲイン・EQ・胸壁距離感） |
| `src/audio/RoomNoiseMixer.ts` | 実習室の環境音、チューブ摩擦、指導者のノック。接触時にducking |
| `src/audio/AudioSession.ts` | ただ一つのAudioContext。最初のイヤーチップ操作で生成/resume |
| `src/interaction/ChestpieceDrag.ts` | 一指ドラッグ。チェストピースは指より上に描かれます |
| `src/interaction/StethoscopeContact.ts` | 接触品質。離すと急に切れず短く減衰します |
| `src/game/WindowDiscovery.ts` | 「そこに留まって数拍聞いた」ことだけを検出します |
| `src/game/DelayedAnatomyReveal.ts` | 聞いた**後**にだけ入る短い内部Reveal |
| `src/game/ComparisonRecorder.ts` | 記録タイル。過去の録音ではなく**場所**を保持し、今の心拍で鳴らします |
| `src/game/ChildGuidance.ts` | 指導者の手。ラウンドが進むほど何もしなくなります |
| `src/game/CameraDirector.ts` | 固定カメラ鎖。自由カメラも一人称もありません |
| `src/render/AdaptiveQuality.ts` | 解像度と影の予算調整。近景の材質差は最後まで落としません |
| `src/scene/` | 実習室、マネキン、聴診器、内部解剖、記録タイルの手続き的生成 |

## 検証

```bash
npm run verify
```

実ブラウザ（Chromium）で一周を通し、以下を検査します。

- 一周（イヤーチップ → 中央 → 第一の窓 → Reveal → 第二の窓 → 四つの窓 →
  一拍目探し → 二拍目探し → 自由遊び）が最後まで進むこと
- 四つの聴診位置・寝台ハンドル・記録タイルが、iPhone/iPad の縦横いずれでも
  画面内にあり、右上の音量ボタンに隠れないこと
- 画面回転で心拍位相・記録タイル・発見済みの窓が失われないこと
- 一回目に聞き比べる二か所が、胸の上半分と下半分から一つずつ選ばれていること
- **音響の実測**：実際のオーディオグラフを `OfflineAudioContext` でレンダリング
  し、僧帽弁領域→三尖弁領域→胸骨中央→肺動脈弁領域→大動脈弁領域の順にS1/S2比が
  単調に入れ替わること、胸表面を横断してもその変化が連続であること
- **シーン負荷**：描画呼び出し数・三角形数・シェーダ数と、描画を除いたシミュレー
  ション時間（フレーム予算の大半を描画に残せているか）
- コンソールにエラー・警告が残っていないこと（低負荷・出荷の両プロファイル）

`?fast=1` を付けると、DPR・影・面光源を落とした低負荷プロファイルで動きます
（ソフトウェアレンダリングでの検証用。実機では不要です）。

### 実測されているシーン負荷

描画呼び出し 103、三角形 22,338、シェーダプログラム 21、ジオメトリ 150、
テクスチャ 15。描画を除いたシミュレーションはフレームあたり中央値 1.9 ms
（ソフトウェアレンダリングでCPUが取られている状態での値）。フレームレート自体
はGPUのある実機／CIで測ってください。

### iOSでの音声の扱い

AudioContext は一つだけで、最初のイヤーチップ操作の中で生成します。着信・Siri・
画面ロックなどで iOS が音声を中断した場合、`statechange` で検知し、**次にどこかを
触った時点で自動的に復帰**します。Safari のページキャッシュから戻ったときは
`pageshow` で心拍スケジューラを取り直します。

## 臨床上の位置づけ

- 舞台は臨床技能実習室、対象は**成人聴診トレーニング用マネキン**です。生身の
  患者や子どもを診察する描写はありません。
- 扱うのは正常なS1・S2だけです。病名・心雑音・弁膜症・正常/異常判定・治療・
  医療判断は一切扱いません。
- 四つの窓は**体表で心音が聞き取りやすい領域**として作られています。弁が真下に
  ある穴としては描いていません。内部Revealでも、弁から体表へ一直線に伸びる線は
  引かず、胸郭を介して振動が広がる様子として見せています。
- 診断用の音声ではありません。

音源のライセンスについては [ATTRIBUTIONS.md](./ATTRIBUTIONS.md) を参照して
ください（すべて実行時合成のため、外部音源はありません）。
