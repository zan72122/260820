# 長生橋ナイアガラ（長岡花火の一晩・第1章）

新潟県長岡市、信濃川に架かる **長生橋** が、夜になると巨大な光の滝に変わる。
その一夜だけの変身を、この章だけで遊べるようにしたものです。

ふつうの道路としての橋を見せ、橋を通行止めにし、橋の長さ方向へ火を走らせ、
最後に橋の下面から黄金の火が一斉に落ちてナイアガラになる ── ここに集中しています。

---

## 起動方法

ビルド不要・依存パッケージなしの静的サイトです。ローカルサーバで開くだけで動きます。

```bash
cd 260820
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

Node があれば以下でも可。

```bash
npx http-server -p 8000 -c-1 .
```

スマートフォンで試す場合は同じ Wi-Fi から `http://<PCのIP>:8000/` を開いてください。
`index.html` を直接ダブルクリック（file://）でも動作しますが、サーバ経由を推奨します。

**横画面推奨。** 縦画面でも成立しますが、構図が変わります（後述）。

## 遊び方（4歳児向け・操作は3つだけ）

| 段 | 操作 | 起きること |
|---|---|---|
| 1 | 🚧 **はしを しめる** | バリケードが降り、通行止めの標識が立ち、車がいなくなる。空が夜に変わる |
| 2 | 🔥 **ひを はしらせる** | 橋の西端から東端へ火が走る。通り過ぎた所から火が垂れ始める |
| 3 | （見るだけ） | 橋の下面から黄金の火が一斉に落ちる。カメラが大きく引いて全長845mの光の滝になる |
| 4 | 🔁 **もういちど** | すぐ最初からやり直せる |

- ボタン以外の画面のどこを触っても、その時の操作が実行されます（4歳児が狙いを外しても進む）。
- 点火中に画面を横へこすると、火の走りが速くなります（任意・できなくても進行します）。
- 説明文は読ませません。アイコン＋2〜4文字の平仮名だけです。
- 右上の 🔊 で消音できます。音は WebAudio による手続き生成（川のざわめき、導火線、燃焼音）。

所要時間は最初のタップから約35秒（closing 5.4s → 点火 7〜8s → ナイアガラ 22s）。

## 画面設計

### 横画面（主）
1. **夕方の川辺** — 信濃川の水際から、13連トラスが対岸へ伸びる。橋脚、街灯、行き交う車
2. **通行止め（寄り）** — 取付道路の上でバリケードが降りる瞬間をアップで
3. **点火前** — 夜になった橋の全景を川面から
4. **点火（追従）** — 走る火を橋と並走して追う
5. **滝（寄り）** — 桁下から落ちる火をトラスと水面の映り込みごと受け止める
6. **全景（引き）** — 845m全部が燃える。手前の河川敷に見物人のシルエット

### 縦画面
横に長い被写体を縦枠に収めるため、**寄りの構図**に切り替えます
（橋の一部＝約40〜60mを大きく見せ、最後の全景だけ橋を画面の対角に沿わせる／わずかにロールを掛ける）。
向きの切り替えは自動検出、開始直後だけ横向き推奨のアイコンを出します。

## 実装メモ

依存なしの Canvas 2D。WebGL は使っていません（モバイルでの確実性優先）。

```
index.html
css/style.css
js/util.js     数学・スプライト生成
js/camera.js   ピンホールカメラ、水平線、被写体自動フィット（縦横どちらでも構図が壊れない）
js/world.js    長生橋の寸法（13径間×65m、桁高13m）と信濃川の岸線
js/fx.js       火の粉・導火線・煙のパーティクル
js/render.js   空／川／映り込み／鋼材／火のカーテン／グレーディング
js/audio.js    手続き生成の音
js/main.js     進行、カメラ割り、入力、負荷の自動調整
```

描画予算は **鋼材・暗い水・落ちる火の粒・薄い煙** に集中させています。

- 水面の映り込みは、水面 y=0 で鏡像した点をそのまま射影して描き、方向性ブラーで滲ませる
- 夕方は橋の「暗い影」が明るい水に落ち、夜は火の「明るい光」が黒い水に落ちる（2枚のバッファを使い分け）
- 川面に伸びるきらめきの道（グリッターパス）が夜景の下半分を支えている
- 火の粉は画面に映っている区間へ寄せて発生させ、寄りでも引きでも密度が保たれる
- 鋼材の色は、区間ごとの点火量と高さから求めた明るさを14段に量子化し、
  線幅も併せてバケット化して1本のパスにまとめて描画（部材は約600本）

### 負荷の自動調整
実測の**フレーム間隔**を見て、粒子上限（1500 → 最小800）→ 内部解像度（最小0.62倍）の順に落とします。
余裕があれば粒子上限を2600まで戻します。物理ピクセルは200万画素、devicePixelRatio は2で頭打ち。

## 残る課題

- **実機での性能は未計測。** この環境の Chromium はソフトウェア描画（SwiftShader）のため、
  FPS の絶対値は判断材料になりません。全画面合成が多い作りなので、
  実機で 60fps に届かない場合は自動調整が粒子と解像度を落とす想定です。
- **縦画面の全景**は、845m を縦枠に収める都合でどうしても橋が細くなります。
  現在はロールで画面の対角を使っていますが、水平線が傾くため好みが分かれます。
- 対岸の岸線が遠景で直線的に見える場面があります（植生の高さで誤魔化していますが完全ではない）。
- 煙は火の量に連動するだけで、風向きの変化や滞留は表現していません。
- 車は行き交うだけで、通行止め時に「引き返す」動きはしていません。
- 音は手続き生成のため素朴です。実録に近づけるなら音源の差し替えが要ります。
- 花火全般（打上げ、尺玉、フェニックス等）はこの章では扱っていません。
