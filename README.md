# 金魚すくい — Kingyo-sukui

夏祭りの夕方。浅い舟に金魚が泳いでいて、手前に乾いたポイが一つ置いてある。

これは「金魚をタップするゲーム」ではありません。本作の中身は、金魚すくい以外では
ほとんど起きない、ひと続きの因果です。

> **乾いた薄紙を水に入れる** → **紙が濡れて弱くなる** → **逃げる金魚の下へそっと差し込む**
> → **破れる前に水面から持ち上げる**

4歳児が説明を一行も読まずに、一回目の操作からこの因果を理解して、
そのまま「今度はあの金魚を」「もっとそっと」と遊び始めることを完成基準にしています。

文字による指示はありません。得点もありません。ゲームオーバーもありません。

---

## 遊びかた

**指一本だけ。**

| 操作 | 起きること |
| --- | --- |
| 画面に触れる | ポイが指に追従し、水面のすぐ下まで沈む |
| 指を滑らせる | ポイが金魚の下へ入る（狙いは大まかで構わない） |
| 上へ払う／**指を離す** | ポイが水面から上がる |

深さは操作しません。ポイがどれくらい沈むかは、指の動きと「いちばん近い金魚が
どの深さを泳いでいるか」から半自動で決まります。4歳児に3Dの奥行きを直接
触らせない、という判断です。

**指を離す＝ポイを上げる**が中核です。触るのをやめるという、どんな子でも必ず
行う動作が、そのまま現実の「すくい上げる」に一致します。

金魚を直接タップして捕まえるショートカットはありません。

## 設計上の判断

**最初の一匹は、ほぼ必ず成功します。**
一匹目だけは遅く、浅く、臆病でなく、判定も甘くしてあります。狙いが数センチ
ずれていても、ポイが本当に真下に入っていればソフトな引き寄せが差を埋めます。
水面を破って金魚が上がり、尾が跳ね、紙がたわみ、水滴が戻る──ここを一度も
カットせずに見せることが、このゲームの唯一のチュートリアルです。

**最初の一枚は絶対に破れません。**
まだ一匹も取れていない子が2分間ポイを振り回しても、紙は濡れて、たわんで、
穴も二つまで開きますが、なくなりはしません。先に紙を失わせると
「紙は破れる」を「紙で金魚をすくう」より先に教えてしまい、順序が逆になります。

**二匹目からが本番です。**
紙は濡れるほど透け、たわみ、亀裂が入り、中央から破れていきます。中央が
抜けても縁で一匹すくえる程度の猶予があります。完全に破れたら、紙は水に
落ちて（ぽちゃん）、屋台の人が別の色の新しいポイを差し出します。失敗画面は
出ません。遊びは止まりません。

**背景はゲーム対象より目立ちません。**
提灯・暖簾・浴衣の人影は、水と紙と金魚のうしろに置いた三枚目のレイヤーです。

## 動かす

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ に静的出力（base は './' なのでどこに置いても動く）
npm run preview    # ビルド結果を 4173 で確認
```

検証は次の順です（`CLAUDE.md` の実行方針に対応）。

```bash
npm run lint       # eslint
npm test           # vitest — 紙と捕獲の純ロジック
npm run e2e        # playwright chromium スモーク
```

デバッグ用のクエリ:

| クエリ | 効果 |
| --- | --- |
| `?fast=1` | 決定論シード・固定解像度・低ティア（自動テスト用） |
| `?tier=low\|mid\|high` | 端末判定を上書きして品質ティアを固定 |

## 中身

```
src/
  game/
    paper.js      濡れ・劣化・破れの純モデル（GLSLと対になっている）
    capture.js    捕獲判定とソフト引き寄せ（速度上限つき＝テレポートしない）
    Game.js       attract → 初回の一匹 → 自由遊び／ポイの交換
  scene/
    Poi.js        枠・柄・濡れた和紙シェーダ（穴・毛羽・たわみ・影）
    Water.js      解析的な波紋、提灯の割れた映り込み、深度でのソート
    Fish.js       頭・胴・尾柄・尾鰭・胸鰭を持つロフト形状＋頂点波の遊泳
    School.js     少数のsteering（徘徊・境界・逃走・引き寄せ）
    Stage.js      舟・受け椀・屋台・提灯・人影・照明
    CameraRig.js  水面に対して30〜40度の再構図（縦は奥行き、横は左右）
    Droplets.js   プールされた水滴。着水で波紋と音を返す
    textures.js   全テクスチャをcanvasで実行時生成（外部アセットなし）
  core/
    Input.js      一指。指を離す＝持ち上げる
    Audio.js      Web Audioによる合成音のみ（主音は水）
    Quality.js    端末ティアと内部解像度の適応制御
    App.js        レンダラ・ループ・可視性・失敗時のフォールバック
```

### 触るときの注意

`src/game/paper.js` の `holeDepth` / `tearWobble` / `sagProfile` は、
`src/scene/glsl/shared.js` の GLSL と**一行ずつ対**になっています。CPU側は
「金魚が取れるか」を決め、GPU側は「子どもに何が見えるか」を決めます。片方だけ
変えると、見た目は紙があるのに金魚がすり抜ける、という形で因果が壊れます。
ユニットテストがCPU側を守っていますが、GLSL側は手で合わせてください。

## 端末まわり

iPhone / iPad Safari を正式対象にしています。

- **WebGL 2 前提ではありません。** WebGPU固有の表現には一切依存していません。
  WebGL 1 でも中核体験は欠けません。WebGLが無い場合だけ、その旨を表示します。
- **内部解像度は測定フレーム時間で上下します**（`AdaptiveResolution`）。落ちるのは
  速く、戻すのは遅く。レイアウトサイズは動かしません。
- **AudioContext はタッチのコールスタック内で生成します。** 次フレームに回すと
  iOS Safari では suspended のままになります。
- **影を落とす光は一つだけ**で、舟のまわりに絞ってあります。提灯は emissive な
  紙と加算のハローで「たくさんの光源らしさ」を作っています。
- 水は流体シミュレーションではありません。解析的な波紋、屋台を映す環境項、
  フレネル、局所的な変形です。水面は透過＋深度テストで描くので、
  「金魚が水面を破った」は深度バッファがそのまま表現します。

参考値（低ティア・縦画面）: 約99ドローコール / 約22,000三角形 / 20プログラム。
外部アセットはゼロ、テクスチャは全て起動時にcanvasで描いています。

> SwiftShader（ソフトウェアラスタライザ）上の実行では、FPS・動きの滑らかさ・
> 最終的な絵の品質は判断できません。GPU・見た目の回帰・性能の確認は、
> ハードウェアアクセラレーションが有効な実機かCIで行ってください。
