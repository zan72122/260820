# 長岡花火の一晩 — 第2章「復興祈願花火フェニックス」

夜の信濃川河川敷。ひとつの火が、川に沿って**横へ横へ**と増えていき、
最後に川ぞい一帯を包む——その一章だけを、単体で遊べる形にしたものです。

外部ライブラリはありません（3D 空間も花火も音楽もすべて自前）。
`index.html` と `src/*.js` を静的に配信するだけで動きます。

## 動かす

```bash
npm run dev          # http://127.0.0.1:5173/
```

同じ Wi‑Fi の iPhone / iPad から試すときは `HOST=0.0.0.0 npm run dev` として
`http://<PCのIP>:5173/` を開いてください。**横画面が主役**です。

URL パラメータ:

| パラメータ | 効果 |
| --- | --- |
| `?fast=1` | 低負荷モード（粒子数・DPR・粒状感を落とす）。E2E でも使用 |
| `?debug=1` | 状態・粒子数・カメラ距離のオーバーレイ |

## 遊びかた

1. 川の**まんなかの一箇所**だけが光っている。そこを触る。
2. 火が点くと、**その両どなり**が光りはじめる。触る／なぞると導火の光が
   水面を走り、次の台船に点く。
3. 点けるほどカメラが引き、川が横に伸びていく。外側の玉ほど大きく、高く上がる。
4. 川ぞいの全地点がつながると、**フェニックス**が一斉に開く。
5. 終わったら「もういちど」。色と広がりかたは毎回すこし変わります。

キーボードでも遊べます（←→ で端から、Space でどこか）。

## 章としての設計

- **小さく始まり、横に大きく終わる。** 見えている川幅は横画面で約 **3.9 倍**、
  縦画面では約 6 倍に広がります（最初は 1 発、最後は 13 発が同時に開く）。
- **操作＝広がり。** 点火できるのは「点いた地点のとなり」だけなので、
  プレイヤーの操作はかならず外へ外へ伸びます。指でなぞると連鎖します。
- **完成の結果としてのフィナーレ。** 全地点がつながったときにだけ、
  5 波のフェニックスが始まります。
- **縦画面は最初から全幅を出さない。** 近いところから始めて、成長に合わせて
  カメラが引き、最後に「こんなに広がっていた」を見せます。

## 中身

| ファイル | 役割 |
| --- | --- |
| `src/camera.js` | 手書きのピンホールカメラ。「見せたい半幅」から距離を逆算する |
| `src/world.js` | 河川敷そのもの。両岸・川面・遠景の町・橋・観客・空気遠近 |
| `src/fireworks.js` | 粒子と玉の型（peony / wide / willow / palm / ring / crackle）、川面の映り込み |
| `src/sites.js` | 川に沿った打上げ地点、導火の光、当たり判定 |
| `src/audio.js` | WebAudio によるオリジナルの合成音（下記） |
| `src/main.js` | 進行・カメラの引き・入力・フィナーレの構成 |

### 音について

既存の楽曲・音源は一切使っていません。すべて WebAudio でその場で合成しています。

- 打上げ音・開花音・ざわめき・歓声：ノイズとサイン波の合成
- 開花音は打上げ地点までの距離ぶん遅れて届き、左右に振られます
- 楽曲：ヨナ抜き（D–E–F♯–A–B）の上で書いた 8 拍の短い動機と、太鼓のパルス。
  つながった数に応じて厚みが増し、フィナーレで対旋律とオクターブが重なります

## テスト

```bash
npm run test:e2e
```

Chromium のみ・workers=1・retries=1・video off・screenshot は失敗時のみ、
という小さなランナー向けの設定です（`playwright.config.mjs`）。
環境に入っている Chromium を `executablePath` で直接使うので
`playwright install` は不要です。

## 既知の制約

- Canvas 2D の自前レンダラです。WebGL は使っていないため、非常に大きな
  画面 + 高 DPR では粒子数が効きます。モバイル判定時は自動的に
  粒子上限・描画品質・観客の間引きを落とします。
- ヘッドレス（CPU ラスタライズ）環境では実機のフレームレートを判断できません。
  実際の描画性能は iPhone / iPad の実機で確認してください。
- 縦画面のフィナーレは構造上どうしても遠景になります（全幅を収めるため）。
  そのぶん手前の観客を近景として残す設計にしています。
