# パカッ！ ひみつのジオード — 設計メモ

対象は四歳児。題材（ジオード）を知っている必要はなく、**一度触れば意味が立ち上がる**
ことだけを条件にしています。以下は、そのために下した判断と、その理由です。

---

## 1. 謎から理解へ

最初の画面には、泥をかぶったゴツゴツの塊が浅い流れに置かれているだけです。宝物らしさは
一切与えていません。その無知が、最初のひとこすりでひっくり返る土台になります。

立ち上がりは三段階に分けました。

| 段 | 起きること | 使う手がかり |
| --- | --- | --- |
| 1 | こすると泥が落ち、下から**ぬれた石**が出てくる | 反射の変化だけ。文字なし |
| 2 | 泥が六割ほど落ちると、**割れ目**と**うっすらした色**が見える | 割れ目に沿った細い発光 |
| 3 | くさびで割ると、すきまから**色のついた光**があふれる | カメラが最接近、時間が一瞬遅くなる |

**割れ目からにじむ色は、なかの結晶とおなじ色**です。洗う作業がそのまま報酬の予告に
なっていて、「洗ったから分かった」という因果が壊れません。ガチャではないのはこのためです。

## 2. 一場面一動詞

`src/game/steps/` に一場面ずつ置いています。各場面で触るべきものはただ一つで、UI の
文字は使いません。

| 場面 | 動詞 | 操作 |
| --- | --- | --- |
| `intro` | （見る） | 二秒強の間。触れば飛ばせます |
| `wash` | あらう | 石をこする |
| `place` | おく | 台までドラッグ |
| `crack` | わる | タップ（三回） |
| `open` | ひらく | 上へドラッグ |
| `dust` | はらう | 結晶の上をなでる |
| `hold` | かざす | 持ちあげて左右にふる |
| `display` | かざる | ビロードへドラッグ |

どの場面も失敗がなく、時間制限もありません。行きづまらないよう、各場面に
「十分やったら次へ」の判定と、時間切れの保険を入れてあります。

### 精密操作をさせない

- つかみ判定はレイキャストに加えて、**画面上で石の中心から 24% 以内なら成功**とします。
  四歳児は狙いません。狙わせません。
- くさびは、タップした場所に自分から移動します。狙うのではなく、叩けば当たります。
- 台へ運ぶ判定は「指を離した位置が中間点より右か」だけ。石の見た目の位置ではなく
  **指の位置**で判定します（重い石は指に遅れてついてくるため）。

### 「こするとまわる」

洗う場面の要は、**こすると石が指の下でまわる**ことです。触れるのは手前側だけなので、
まわらなければ裏の泥に永久に届きません。まわるからこそ、「こすりつづける」という
四歳児が唯一思いつく行動だけで、全面が洗えます。

## 3. カメラ

自由視点は与えていません。場面ごとにショットが決まっていて、`src/game/shots.ts` に
一箇所でまとめてあります。

```
intro   引き   「何かの石がある」
wash    寄り   「自分の手が触れている」
place   引き   「置く先がある」
wedge   寄り   「道具と割れ目」
crack   最接近 「これを見ろ」          ← 転換点
reveal  引き   「石ぜんたいが変わった」
dust    寄り   「一粒ずつきれいになる」
hold    引き   「部屋に光が散る」
display 寄り   「これがきみの石だ」
```

画角は縦横比から距離を逆算しています（`CameraRig.solve`）。被写体の半径を指定し、
端末の縦横比に合わせて距離を決めるので、iPhone SE でも iPad でも同じ構図になります。
極端に縦長な端末で距離が伸びすぎないよう、縦横比は 0.60 で頭打ちにしています。

## 4. 材質

主役材質はすべて**フラグメントシェーダで手続き生成**しています（`src/gfx/materials.ts`）。
焼き込みテクスチャを使わなかった理由は二つです。

1. 割れる瞬間にカメラが極端に寄るため、どんな解像度でも足りません。3D ノイズなら
   どこまで寄ってもディテールが出ます。
2. スマホのテクスチャメモリと初回ロードを、主役以外に使いたくありません。

色分けではなく**光への応答**で材質を分けています。

| 材質 | 見分けかた |
| --- | --- |
| 乾いた岩 | 粗さ 0.85 前後、鋭い稜線、拡散のみ |
| ぬれた石 | 粗さ 0.30、色が半分に沈み、環境の映り込みが出る |
| 泥 | 粗さ 0.96、塊状の凹凸、映り込みなし |
| 金属 | metalness 1、細い研磨筋、くもり |
| ビロード | sheen、斜めから見ると縁が明るい |
| 毛 | 先端が明るく透ける、フレネル強め |
| 水 | 真上からは透け、浅い角度では鏡になる |

泥・ぬれ・粉は**指で塗るマスク**です（`src/gfx/PaintMask.ts`）。ジオードは UV 展開
していません。シェーダと CPU が同じ射影（外側は equirect、空洞は円板）を共有するので、
触った場所がそのまま落ちます。ストロークは前フレームからの弧を補間して塗るため、
フレームレートが落ちても線が途切れません。

### 手続きノイズのちらつき対策

手続き高さ場にはミップマップがありません。そのままだと遠景やかすめ角でハイライトが
白い粒になって暴れます。高さ場のスクリーン空間微分から粗さを持ち上げる処理を
`proceduralMaterial` に共通で入れてあります（Toksvig 近似）。

### ブルーム

画面全体を光らせません。しきい値を 1.0 に置き、結晶の縁のフレネル発光だけが越えるよう
調整しています。工房は最後までマットなままで、きれいなのは結晶だけです。

## 5. 割れかた

物理シミュレーションは使いません。上下の殻は**共有した割れ面プロファイル**から生成する
ので、閉じたとき必ず噛み合います（`geodeGeometry.ts` の `seamOffsetAt` / `breakProfile`、
検証は `src/test/geode.spec.ts`）。閉じているときも 0.7% だけ隙間を空けています。同一面
どうしはモバイル GPU で必ず z-fighting を起こすためです。

くさびは三回で割れます。ただの連打ではなく、**叩いた場所に応力がたまり、同じ場所を続けて
叩くと効きが良くなる**ようにしました。応力は割れ目に沿った光として見えます。石を割る人が
実際に覚えることを、そのまま遊びにしています。とはいえ五回叩けば必ず割れます。

開く動きは、少しだけ口が開いたあと、フタが弧を描いて裏返り、椀の後ろに落ち着きます。
実際に割れたジオードが机に置かれている姿です。ちょうつがい式（貝殻式）も試しましたが、
90 度で自由端が直径ぶん跳ね上がり、構図が壊れました。

## 6. 音

すべて WebAudio の合成です（`src/audio/Audio.ts`）。ファイルを読まないので、通信環境に
関係なく最初の一秒から鳴ります。

- こする音とくさびのきしみは**指に追従する連続音**（帯域と音程が速度で動く）
- 割れる音は、鋭いトランジェント＋石の胴鳴り＋低い余韻の三層
- 報酬のチャイムはペンタトニックを上に登るので、繰り返しても「進んでいる」音になります

iOS の制約から、AudioContext は最初のタッチで生成します。

## 7. 性能

- 描画コールは常時 20 前後。ジオードは半球あたり 2（岩＋晶洞）＋結晶 1（インスタンス）。
- 追加アセットはゼロ。ビルド成果物は JS 約 190 KB gzip のみ。
- 画質は三段。フレーム時間の 70 パーセンタイルが 34fps を割ったら**一度だけ**下げます。
  行ったり来たりする自動調整は、一定して低い設定より気が散るためです。
- `dt` は 0.1 秒で頭打ち。それ以上刻むと、遅い端末でゲームがスローモーションになります。
- `?fast=1` で DPR 1・ブルームと火花なし・粗い形状にします（E2E 用）。

## 8. やらなかったこと

- **連打ゲームにしない** — くさびは三回で、場所に意味があります。
- **破壊ゲームにしない** — 割ったあとの工程（はらう・かざす・かざる）のほうが長い。
- **ガチャにしない** — 結晶の色は洗う前から割れ目に見えていて、輝きは洗いと払いの丁寧さで
  決まります。
- **長文を出さない** — ゲーム中の文字はゼロ。読み上げ用の `aria-label` だけ付けています。
- **正確な破砕シミュレーションをしない** — 制御されたアニメーションのほうが、毎回きれいに
  割れます。
